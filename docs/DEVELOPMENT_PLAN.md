本地优先、个人使用的多 AI 编程 Agent 工作台。借鉴原视频的产品交互理念，保留用户自己的 CLI/认证配置，统一项目、会话、执行状态和文件操作。

## V0.2 授权流程

```text
用户发送任务（选择 plan 或 edit）
  ├─ plan：按各 CLI 支持的受限模式立即执行
  └─ edit：创建待授权任务（尚不启动进程）
       ├─ 批准本次执行：按各 CLI 的编辑模式启动
       ├─ 拒绝：记录拒绝，不启动该任务，继续后续队列
       └─ 停止/重启：销毁等待授权及队列，不自动恢复
  -> 事件以 JSONL 读取（只抽取展示文本、工具类别/状态与 Token）
  -> 结果存储本地、SSE 通知浏览器
```

**这是任务级授权，不是逐条工具调用审批。** `plan`/`acceptEdits`/`accept-edits` 等参数的实际能力是厂商 CLI 定义的，不作为 AgentDock 的安全隔离。不得使用 `--dangerously-skip-permissions` 等绕过参数。

## 自动化验证

```bash
npm run check
npm test
```

所有模拟 CLI 在 `test/fixtures/fake-agent.mjs` 输出可控 JSONL，测试真实本地子进程的生命周期：stdout、stderr、exit code、进度、Session ID、超时/停止与任务授权。**不会**调用模型 API，不应把模拟验收写成真实 CLI 端到端已通过。

## 风险、缓解与设计债

- 厂商 CLI 参数与 JSONL 结构可能发生变更：增加真实 CLI 版本矩阵并锁定兼容范围；不在未知版本静默绕过权限。
- 原生 App 会话存储和 CLI 会话 ID 可能不一致：只使用官方公开的接续接口，未验证前不承诺无缝切换。
- `plan` 不是通用安全沙箱：进程沿用本机账户权限；重要操作须使用隔离账户/工作区/容器或系统沙箱。
- 可写 Agent 可能修改本地项目外的内容（取决于 CLI 和插件）：禁用危险参数、确认受信任项目、尽量采用 Git worktree，后续考虑 OS 沙箱。
- 事件中可能含敏感工具参数：UI 仅显示工具类型、状态，不展示完整命令及工具输入/结果。
- 会话与项目状态目前为本地单 JSON 文件：有单进程写入假设，未来需要 SQLite 和加密/备份选项。
- HTTP SSE 全量刷新影响大日志性能：后续采用节流、增量事件、分页历史。
- 浏览器文件拖拽无法安全提供用户原文件完整本地路径：仅创建受控副本，需谨慎区分本地复制与发送模型。

## V0.3 隔离工作区与并发限制

- 可写任务勾选隔离选项后，只有本次授权被批准才会创建新的 detached Git worktree；不对原目录执行写入，不自动合并与删除。
- 基线来自 HEAD，源项目工作树中的未提交文件、未跟踪文件不会被带入；显式附件会复制进 worktree。
- 不为隔离工作区复用原项目的 CLI session ID，也不允许其覆盖原会话 ID。
- 默认最多同时运行 3 个 Agent 任务，不同会话可排队并允许用户取消队列；单会话仍串行。
- 真实厂商账号/客户端未安装于测试环境，测试仅证明调度、Git worktree、CLI 模拟输出及本地 HTTP 链路。
- 详见 `docs/WORKTREE.md` 与 `docs/CLI_COMPATIBILITY.md`。


## V0.4 故障恢复与差异预览

- 不自动恢复未完成的任务，重启后其状态为 `interrupted`；任务前批准失效。
- 用户仅可显式重试失败/中断任务，且可写任务需要重新批准；历史为每会话最多 150 条元数据，复用原消息作为重试输入。
- 每个 Git 变更文件通过只读 diff 端点检查；不执行自动应用、合并或删除。
- 详细机制见 `docs/RUN_HISTORY.md`。
