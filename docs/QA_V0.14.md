# AgentDock V0.14 · 任务控制与连接恢复 QA

## 目标与改动

- 排队中的任务（状态 `queued`）会显示“取消排队”，与运行中“停止任务”、待授权“撤回任务”区分。
- 取消、批准、拒绝请求在提交期间不能通过重复点击产生额外请求。
- 首次加载失败后提供“重新连接”入口；SSE 中断显示重连状态及手动重新同步操作。
- 网络掉线期间的定时刷新不会不断重复弹出相同 Toast。
- 不修改运行队列或授权服务端语义，不修改持久化数据结构或供应商 CLI 参数。

## 自动化验收

1. `npm run check`：语法检查。
2. `npm test`：原有测试与新增 UI VM 行为测试、HTTP 并发排队取消测试。
3. 新增 UI 行为测试覆盖：排队可取消；同一待批准任务只能提交一次；请求失败后允许再试；运行中停止请求未完成前不能错误显示已结束。
4. HTTP 测试覆盖：三个 Demo 会话占满全局槽位，第四个任务排队、收到停止请求后标记 `stopped`，不生成 Agent 回复。
5. 独立 HTTP 冒烟验证 `api/health`、版本号、页面重连入口和 Demo Agent 完成。

## 待实机验收

- 在用户本机浏览器中，断开/恢复本地服务后检查连接状态、恢复按钮、键盘焦点。
- 在已登录 Codex/Claude/Antigravity CLI 的真实机器上，验证发出停止信号后实际进程完全退出及工作目录状态。
- 移动端窄屏和高对比度下检查任务状态按钮与连接提示是否可读。

**边界：** 浏览器自动截图在当前隔离环境中未成功，不计入本版已验证项；任务取消不回滚 Agent 已修改的文件。
